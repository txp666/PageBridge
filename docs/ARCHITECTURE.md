# 架构与数据流

本文描述 0.3.0 / build 12，包含通用文档助手、独立模型选择、OpenAlex 文献检索、Sci-Hub 全文获取与 Sparkle 自动更新。阅读工作区、引擎与归档的分版本验证见 [验证记录](VERIFICATION.md)。本次发布沿用既有翻译引擎，历史译文结论仍绑定原运行与输出哈希。

PageBridge 的窗口、设置、导入导出为 SwiftUI / AppKit，PDF 阅读器使用 PDFKit。浏览器原型不参与原生运行。独立 Python worker 使用 PDFMathTranslate-next / BabelDOC 处理版面和翻译，本机 Ollama 或用户选择的 API 提供语言模型。

## 阅读工作区

`LibraryStore` 通过独立 `library.json` 按文档 UUID 保存文件夹归属、收藏、最近打开时间和回收时间。`documents.json` 继续保存原有文档记录与名称；没有 sidecar 的旧记录默认未分类。修改先读取并验证当前分类文件，再原子写入；损坏或未知版本拒绝覆盖。删除文件夹只清除归属，回收与恢复只改变元数据，不移动或删除 PDF。`LibraryModel` 管理筛选、名称搜索和排序，`LibrarySidebar` 提供入口；翻译中的重命名与回收应在应用动作入口和侧栏都被阻止。

`PDFPreviewCache` 在独立 actor 内读取 PDF、生成缩略图和提取内置大纲，向 SwiftUI 返回 PNG 数据或目录项，不在阅读器之间共享 `PDFPage`。缓存同时限制文档数、缩略图数与字节数。个人书签来自阅读元数据，PDF 目录来自源文件，两者分别展示；没有大纲时不生成推测目录。

`ReaderWorkspace` 管理当前原文／译文选区、页面和批注。`AnnotationStore` 按文档 UUID、PDF 变体与实际文件 SHA-256 绑定高亮、下划线、笔记和书签；选区坐标保存为原生 PDF 页面坐标。保存及导出时核对文件哈希，重新翻译的文件不复用旧坐标。屏幕上的批注作为 PDFKit 叠加显示；工作文件不原位改写。批注 PDF 导出重新打开对应文件并应用叠加，保留源注释；Markdown 导出包含来源变体、页码、摘录及哈希。个人书签不转换成 PDF 内置大纲。

## 在线文献检索

侧栏和 `+` 菜单打开原生 `LiteratureSearchView`，`LiteratureSearchModel` 独立管理检索、分页和下载状态。`LiteratureSearchClient` 请求 OpenAlex `/works`，标题／关键词使用普通搜索，DOI 或 doi.org 链接规范化后使用 DOI 精确筛选；每页最多 20 条，支持加载更多及 `is_oa` 筛选。只有用户提交搜索或加载更多才发送请求，修改输入／筛选条件清空旧结果。请求代次与 Swift Task 取消共同阻止已取消或过期响应覆盖当前界面。

`LiteratureFullTextSource` 将元数据检索与全文来源分开：默认 `.sciHub`，也可选择 `.openAccess`。来源及 Sci-Hub HTTPS 地址通过 AppStorage 保存在本机，默认地址为 `https://sci-hub.ru`。更改来源或地址不自动发起网络请求；点击“打开全文”时捕获所选来源、地址和 DOI。

Sci-Hub 路径由 `SciHubResolver` 按 DOI 请求文献页面，解析页面提供的 PDF 链接，再交给现有下载器。它直接适配网页，不依赖或宣称存在稳定官方 API；页面结构、域名和收录情况变化都可能导致获取失败。检索命中只证明 OpenAlex 有该记录，不证明 Sci-Hub 已收录全文。没有 DOI 的结果不能使用此路径。公开 PDF 路径仍只采用 OpenAlex 明确标记为开放获取的位置；原文页面单独保留，不能当成 PDF 下载。

输入可在本机规范化为 DOI 时，空结果区域提供“直接打开此 DOI 的全文”。此路径直接进入 Sci-Hub 解析，不依赖 OpenAlex 查询成功或完成；标题／关键词仍通过 OpenAlex 获取结果和 DOI。已有结果使用对应结果卡的“打开全文”。

两个来源共用 `LiteraturePDFDownloader` 的独立临时会话，响应流写入临时目录，下载总量上限为 100 MB；初始 URL 和每次重定向均检查 HTTPS 与公共网络目标，不携带翻译密钥、授权头或浏览器登录状态。下载后检查 PDF 标识、完整性及 PDFKit 可读页面；登录页、验证码、加密或无效文件不进入文档库。解析和下载共用任务取消与代次检查，取消、失败及导入结束清理本次临时文件。错误保留来源页面入口。解析器不执行网页脚本，也不关闭 TLS 验证。

`SciHubBrowserView` 提供可选的临时 WebKit 窗口，使用默认浏览器行为和 nonPersistent 数据存储，让用户在页面完成网站验证。它不模拟点击验证码，不调用验证脚本；网页自身的脚本由 WebKit 正常运行。加载完成后只读提取有限 HTML，通过同一个 DOI/PDF 地址解析器回调，再交给匿名下载器；不从 WebKit 导出 cookies 或凭据。关闭时停止加载并使旧回调失效。需要登录状态的 PDF 可能仍需在浏览器中处理。

域名预解析兼容本机 TUN 代理使用的 `198.18.0.0/15` 合成地址，请求仍使用公共域名并保留系统 HTTPS 证书验证；直接指向该网段的 IP URL 仍被拒绝。其他私网、回环和链路本地地址继续拒绝。预解析与 URLSession 实际解析并非 DNS 固定绑定，不将其视为完整网络隔离。

校验后的文件通过 `AppModel.importLiteraturePDF` 进入现有文档库：先核对下载文件 SHA-256 与未回收记录及其实际原文副本，相同则选中已有文档，不覆盖名称、批注或译文；否则调用原导入流程创建独立副本、保存文档记录并按当前文件夹归类。记录保存失败只清理本次新建的导入目录。成功导入后打开阅读器，翻译和助手请求仍需用户另行触发。

检索不依赖 `ServiceConfiguration`、Keychain 或 Python worker，不使用语言模型。OpenAlex [当前认证说明](https://help.openalex.org/api/authentication/)支持匿名基础查询，但有额度和频率限制；客户端明确呈现限流或网络错误。搜索只发送搜索词及筛选／分页参数；Sci-Hub 全文请求发送 DOI 到已配置站点，随后下载其页面提供的 PDF；公开 PDF 路径直接连接对应文献提供方。本机 PDF、批注与翻译服务密钥不进入这条链路。

## 文档助手请求

助手由 Swift 的 `PaperAssistantContextBuilder`、`PaperAssistantService` 和 `PaperAssistantModel` 实现，不经过整篇翻译 worker。它复用现有 `ServiceConfiguration` 和 Keychain；助手选择独立于翻译服务，以 `PageBridge.assistantServiceID` 保存在 UserDefaults。未选择或已删除的配置回退到当前翻译服务，再回退到首个配置。用户明确发送时捕获服务、同一服务 ID 的密钥、文档 ID 与输入哈希。打开面板或切换模型只更新本地状态，不发送文档。请求返回后仍写回捕获的文档，不根据当前界面选中文档重定向结果。

文档问答在本机最多抽取 500 页、240,000 个字符，然后根据当前页、可识别的概述／目的／摘要／结论、要求／步骤／注意事项和问题词选择最多 6 页片段。具体问题命中的页面优先于泛用指导章节。发送证据总量不超过 12,000 个字符、每页最多 2,400 个字符；选文模式最多 6,000 个字符。问题最多 2,000 个字符，近期历史最多 10 条、8,000 个字符。自由提问不新提取 PDF，但仍可能携带之前包含文档内容的对话。读取了多少本地页面与实际发送哪些片段分别记录，不能把本地扫描描述为模型通读全文。界面采用通用文档表述，内部 `.paper` 序列化值保留以兼容旧历史。

模型被要求只引用本次提供的 `[P页码]`。响应解析仅把本次证据中的页码生成为可展开、可跳转的引用；其他页码明确标记未核验。该映射不验证引用内容是否支持模型的结论。模型输出按文本显示，不自动执行其链接、工具要求或文档内指令。网络请求不跟随重定向，响应有字节、字符及生成长度限制；截断响应作为错误处理。

每份文档的对话按 UUID 与输入哈希保存到独立 JSON，持久历史最多 40 条并限制总长度，包含问题、回答及引用片段，不包含密钥。助手取消与翻译任务取消分别管理；本地对话和导出的笔记都可能含敏感文档内容。未检索到的内容、图片文字和不可靠的公式文本层可能无法回答。提示要求指出证据不足，但不保证模型不会猜测，回答仍需人工核对。

## PDF 翻译链路

1. 导入检查 PDF 并在应用数据目录创建副本，记录输入 SHA-256。
2. 每次任务创建新 attempt。Swift 从 Keychain 读取密钥，通过子进程 stdin 发送请求；命令行与持久配置不保存密钥。
3. worker 解析源文档、记录源字形/段落结构，保护变量、数值、元数据、目录、索引与列表。
4. 每段模型回复经过占位符、公式原对象、数字/技术标识与翻译完整性检查；有问题时按完整语境重试，无法恢复则任务失败。
5. 排版阶段保持有证据的脚标与列表关系。链接基于源到译文的内容映射恢复，不把源链接框盲拷到重排后页面。
6. 输出重新读取，验证页数、源哈希和标签，记录链接恢复统计。内容保护检查通过后一次提交新译文、双语文件及 manifest；链接热点和目标正确性还需要最终页面复核。
7. Swift 原子更新文档记录。失败或取消保留上次成功结果；导出只复制已提交文件，禁止覆盖应用管理目录。完整性失败时先从固定报告路径重建有大小上限的白名单诊断，存入文档的 `diagnostics/<attempt>.json`，再清理临时目录。摘要只保留计数、固定原因、布局类别及段落 SHA；未知字段和任意错误字符串不进入持久化文件。界面按是否存在旧译文给出提示，不把首次失败描述成已保留旧结果。

跨栏上下文在调度前从源阅读顺序、版面与字形证据共同确定的连续正文边缘提取，只提供公式前或公式后的连续片段，不删除公式后拼接两侧内容。上下文只辅助理解当前段落，不合并段落或把相邻数字、公式补进译文。源结构明确的短连接词在上游长度过滤前处理，期刊页脚与出版日期元数据保留原样。

另有独立的源分段修复：同页相邻两栏中，栏尾未结束的短纯正文片段在语法、基线、字体和阅读顺序均明确时移至下一栏段首，再交给模型翻译。仅移动原字形对象，保持全文字形顺序、两段原有目标框和样式；公式、引文、脚标和跨页片段不参与。这样模型能读到完整句子，排版仍使用原来的单栏区域。无法翻译已重分段的段落时必须失败，不能把原位置的字形作为成功译文提交。

另一个独立且更窄的规则处理隔着一页纯图版的断词续句：须同时证明连续物理页、图版页无正文、页边弃用块确为有限页眉／页脚、同一字体资源、栏尾至下一正文页栏首的几何和真实字形断词。仅将前页最后一个短纯文本句头的原字形所有权移到续段，组成完整翻译输入；不移动公式和引用，保留两段目标框，禁止失败时静默回退原文。每个字形的字段及正文相对顺序保持，但跨页归属和相对浮动图注的遍历位置改变，不能宣称全局遍历顺序不变。原 PDF 文件不改，最终双语原文页必须另行逐页核对。

列表分段按源行和悬挂缩进判断。对旧字体把圆点编码成字母的情况，要求精确字体／CID、重复行首及不同正文字体／字号／几何证据；不改原始字形。参考文献只有在上一物理行以 `Accessed` 结尾、本行是完整有效日期且位于正文悬挂列时，才将该日期排除出编号候选；混合有点／无点编号继续按原路径处理。

跨页修复由另外两条窄规则处理：补全在分页处断开的计数比定义，以及连接被分页拆开的科研列表短语。只接受相邻原页、明确首尾正文位置、完整源语法和一致的原生字体资源；移用已有纯文本字形，保留原公式、段落目标框和字形属性。选页缺口、字体资源不一致或正文之间有其他内容时不猜测拼接。列表中孤立的 `In` 仅在与后文同基线且字形相邻时接回；原公式包含项目符号和长度值时，译文须保留这个原对象及紧随其后的单位在条目开头。

另一类断句需要把下一栏或下一页开头的一小段纯文本接回前段末尾。该路径要求明确的未完成语法、原生单行字形、相邻阅读顺序与一致字体资源，保留两段目标框及全部原公式。它与前述“栏尾接到下栏”规则方向不同，不能仅凭文本相邻就混用。只读比较 PDF 的颜色状态时不得改变原字形的延迟缓存。

若完整纯文本句子被分在两栏的两个短框中，且不含公式、引文或富文本，可绑定为一个逻辑翻译输入，随后沿两个原框连续排版。任一段含已捕获的源链接时跳过此合并，防止原整段链接扩展到另一段文字。绑定依赖源对象身份，伙伴框保持保留状态；不允许把它当成空闲区域扩展其他段落。每个输出字形都需落在原框内，字号不得低于原字号的 75% 或 7 pt 中较大的值；装不下即失败，不启用上游扩框兜底。独立排版测试之外，还要通过完整页面预处理和 PDF 导出检查。

同栏标题或正文被错误分块时，只有原语法仍开放、字号/字重/颜色一致、几何近邻且合并区域没有其他内容，才拼接原组合并取原框并集。不同字体子集资源仍逐字保留；名称中的原生加号也保持原公式对象。标题可读取紧随其后的源正文片段作为有限背景，但背景不能被补写进标题译文。

姓名附标仅在源作者列表或带连字符的专名、基线及附标与元音的几何关系都明确时，与原字母组成不可拆分的字形组。源文件中的重叠印字仍保留所有原对象；只有同页已证实的普通词，才在模型请求中消除重复字母。跨栏网址则要求左段以 HTTP(S) 路径分隔符结束，右段以紧邻的短路径开始；只移动原字形以补全地址，不凭文字创建新的链接注释。

原生姓名组在创建时登记原页、段落、公式容器和逐字形身份及属性，随后绑定到当前文档与精确翻译输入；不能仅凭公式中的文字像姓名就允许换位。在没有富文本标记的正文中，已登记且唯一的姓名占位符可以适应中文语序移动，但姓名之间的顺序、全部占位符的数量，以及其余数学占位符的顺序必须保持。源句符合已识别的双网络得分语法时，还要检查网络与得分的对应关系。文档、原对象或属性发生变化即失去该许可；这条规则不允许一般数学公式自由重排，也不提供通用语义等价保证。

分类标识的标签、编号和范围继续受保护，编号之间的普通 `and/or` 可译为等义中文连接词。校验同时检查逻辑关系和有序编号，不能仅比较数字出现次数。电气输入／输出定义、训练与预测时间、实验条件与测量量等检查只在原句有明确证据时触发，错误响应走原完整段落重试路径。

中文目标下，完整的短物理量标签 `Voltage U`、`Current I`、`Power P`、`Inductance L`、`Capacitance C` 还须保留量名与单字母符号的明确配对。可带原项目符号；若它由公式占位符承载，必须核对为已注册的原生单项目符号对象。检查要求对应中文量名、原字母及出现次数完整，例如 `Power P` 不能变成“电源”或丢掉 `P`。引用、代码、句内片段、歧义标点和不匹配的符号不由这条整项规则处理；非中文目标保持原有行为。错误结果通过正常校验失败和完整段落重试恢复，不直接修改 PDF 或替换模型输出。

源文档明确的术语定义也在调度前捕获。例如只有原生正文已定义 CWT、A/C 的天气含义时，相关段落才得到相应提示和错义检查；缺少定义或存在冲突时不推断。这类绑定与当前文档及原公式对象关联，整段恢复时仍校验，不能沿用到另一文档。源语法明确时，模型的英文请求视图可以拆开丢失的词间空格、明确指代或关系；原始翻译输入、数字和公式始终是最终校验依据。

源年份范围若被解析成相邻三段，仅在同基线、字体、字号、XObject 和字形邻接关系明确时合并，并保留原字形对象。数字保护标记只用于源语法证明的双组省略比较或明确预测输入/输出关系的整段恢复；其他数字保持可读，恢复后仍校验数字及出现次数。

当源英文明确给出两个并列量、单日目标和前序输入时，模型请求可以将 `the last` 展开为源句已指明的目标，避免模型把它理解成“最后一个序列”。原始输入仍用于全部内容校验，不改公式对象、数字或生成的中文；出现额外候选指代时不做这种展开。当前真实完整摘要探针由一次正常重试修复，未触发预测数字标记恢复；后者目前由离线测试覆盖。这些局部修复不代表五份全文或最终包已通过。

公式识别前，对原字符证明的正文换行恢复独立物理行，防止上游按同一行标识合并跨行公式和普通数字。原生公式描述符、小数与图表标题碎片只有在源语法和字形邻接同时明确时才重新绑定；不从模型回复生成原数学字形。数字检查将合法英文序数词与对应阿拉伯数字统一比较，其他技术标识仍保留独立检查。月份、否定术语及少量已确认的句法错误检查用于触发完整段落重试，不提供一般语义等价保证。

## 存储

应用数据位于 `~/Library/Application Support/PageBridge/`，元数据采用原子 JSON 文件。`documents.json` 保存文档记录，`services.json` 保存无密钥的服务配置，`library.json` 保存分类状态；`annotations/<文档 UUID>/<原文或译文>/<PDF 哈希>.json` 保存版本绑定的批注，`assistant/<文档 UUID>.json` 保存有长度上限的对话。每份文档拥有原始副本和独立结果目录；导出文件位于用户在保存对话框中选择的目录。API Key 仅在 macOS Keychain 中存储。上游资源与历史缓存可能在其他用户缓存目录，具体位置见 [引擎说明](../engine/README.md#cancellation-diagnostics-and-storage)。测试日志与模型调试响应可能含文档文字，不属于可公开发布的源代码。

## 本地与在线

PDF 解析、排版、预览、批注和证据片段提取在本机完成。选择本机 Ollama 时语言模型也在本机；选择在线厂商时，待翻译文本或助手的问题、证据片段及近期对话发送至配置的 API。翻译与问答均复用已选服务，但具有各自的请求生命周期。下载所需字体和版面模型、安装本机语言模型后才具备完全离线运行条件。示例导入和打开助手面板不会自动调用模型。

在线文献检索、Sci-Hub 全文解析和 PDF 下载需要联网，生命周期独立于翻译与问答；关闭检索窗口会取消未完成的检索、解析和下载。导入后的 PDF 可按普通本地文档继续使用，离线时不提供新文献搜索。

## 更新与发行

`UpdateController` 保持 Sparkle 2.10 的原生更新控制器。`update-config.json` 记录固定 GitHub 仓库、公开 feed 地址和 Ed25519 公钥，组装时写入应用 Info.plist。feed 与应用 ZIP 均须验证签名，下载包在解压前验证；更新只使用 HTTPS，关闭系统概况上报和静默安装。自动检查使用 Sparkle 自身的授权与持久化偏好，用户也可从应用菜单手动检查。

翻译运行时阻止新的更新检查，已经下载的安装通过 `UpdateInstallationGate` 延后至任务结束。更新重启与开始翻译发生竞争时，AppDelegate 拒绝更新触发的退出，避免取消翻译。更新替换应用包，文档、批注、设置和 Keychain 位于包外，不属于替换目标。

`v*` 标签触发 GitHub Actions：核对版本与 build、测试、构建、验证包、生成应用及对应源码归档。CI 仅在签名步骤读取仓库 Secret；私钥写入权限受限的临时文件后交给官方 Sparkle 工具，完成或失败均清理。独立验证脚本只用公钥检查 feed 和 ZIP，拒绝 build 回退。发布先创建 draft，核对上传文件的大小与 SHA-256，再公开为 latest；公开下载和更新源还会再次校验。具体命令见 [开发与发布](DEVELOPMENT.md)。

当前发行采用 ad-hoc 应用代码签名。Sparkle 更新签名不等同于 Apple Developer ID 签名或公证，首次安装仍可能需要用户在系统设置中允许打开。

## 兼容与质量边界

只接入 OpenAI Chat Completions 兼容接口的厂商预设；不把只支持其他协议的厂商伪装成兼容端点。模型列表和可用权限以用户账户的接口返回为准，预设是便捷起点。

保留文本层 PDF 的主要结构，不提供通用 OCR。图片中的英语与无法可靠识别的图表短标签不会凭空重写。源文本抽取存在旧字体/Unicode 映射差异，数学质量以源字形和最终渲染为依据。自动门、单元测试、真实模型任务和人工页面复核各自提供不同证据，不能相互替代。

### 批注交互边界（0.2.1）

显示层只接管本次渲染产生的实际批注对象；便笺单击和批注右键转到 `ReaderWorkspace` 编辑器，经 sidecar 保存后刷新 PDFKit 热区。高亮、下划线显示时不附原生评论气泡，导出时仍写入完整 `contents`。链接／表单及普通文字选择沿用 PDFKit；源 PDF 内嵌批注保留原生处理。编辑前快照原文／译文绑定，返回时重新核对，防止文档切换或重新翻译时错写。
