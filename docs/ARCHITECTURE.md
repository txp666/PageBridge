# 架构与数据流

本文描述 0.1.4 源码；当前实际验收范围见 [验证记录](VERIFICATION.md)。

PageBridge 的窗口、设置、导入导出为 SwiftUI / AppKit，PDF 阅读器使用 PDFKit。浏览器原型不参与原生运行。独立 Python worker 使用 PDFMathTranslate-next / BabelDOC 处理版面和翻译，本机 Ollama 或用户选择的 API 提供语言模型。

1. 导入检查 PDF 并在应用数据目录创建副本，记录输入 SHA-256。
2. 每次任务创建新 attempt。Swift 从 Keychain 读取密钥，通过子进程 stdin 发送请求；命令行与持久配置不保存密钥。
3. worker 解析源文档、记录源字形/段落结构，保护变量、数值、元数据、目录、索引与列表。
4. 每段模型回复经过占位符、公式原对象、数字/技术标识与翻译完整性检查；有问题时按完整语境重试，无法恢复则任务失败。
5. 排版阶段保持有证据的脚标与列表关系。链接基于源到译文的内容映射恢复，不把源链接框盲拷到重排后页面。
6. 输出重新读取，验证页数、源哈希和标签，记录链接恢复统计。内容保护检查通过后一次提交新译文、双语文件及 manifest；链接热点和目标正确性还需要最终页面复核。
7. Swift 原子更新文档记录。失败或取消保留上次成功结果；导出只复制已提交文件，禁止覆盖应用管理目录。

跨栏上下文在调度前从源阅读顺序、版面与字形证据共同确定的连续正文边缘提取，只提供公式前或公式后的连续片段，不删除公式后拼接两侧内容。上下文只辅助理解当前段落，不合并段落或把相邻数字、公式补进译文。源结构明确的短连接词在上游长度过滤前处理，期刊页脚与出版日期元数据保留原样。

另有独立的源分段修复：同页相邻两栏中，栏尾未结束的短纯正文片段在语法、基线、字体和阅读顺序均明确时移至下一栏段首，再交给模型翻译。仅移动原字形对象，保持全文字形顺序、两段原有目标框和样式；公式、引文、脚标和跨页片段不参与。这样模型能读到完整句子，排版仍使用原来的单栏区域。无法翻译已重分段的段落时必须失败，不能把原位置的字形作为成功译文提交。

跨页修复由另外两条窄规则处理：补全在分页处断开的计数比定义，以及连接被分页拆开的科研列表短语。只接受相邻原页、明确首尾正文位置、完整源语法和一致的原生字体资源；移用已有纯文本字形，保留原公式、段落目标框和字形属性。选页缺口、字体资源不一致或正文之间有其他内容时不猜测拼接。列表中孤立的 `In` 仅在与后文同基线且字形相邻时接回；原公式包含项目符号和长度值时，译文须保留这个原对象及紧随其后的单位在条目开头。

另一类断句需要把下一栏或下一页开头的一小段纯文本接回前段末尾。该路径要求明确的未完成语法、原生单行字形、相邻阅读顺序与一致字体资源，保留两段目标框及全部原公式。它与前述“栏尾接到下栏”规则方向不同，不能仅凭文本相邻就混用。只读比较 PDF 的颜色状态时不得改变原字形的延迟缓存。

若完整纯文本句子被分在两栏的两个短框中，且不含公式、引文或富文本，可绑定为一个逻辑翻译输入，随后沿两个原框连续排版。任一段含已捕获的源链接时跳过此合并，防止原整段链接扩展到另一段文字。绑定依赖源对象身份，伙伴框保持保留状态；不允许把它当成空闲区域扩展其他段落。每个输出字形都需落在原框内，字号不得低于原字号的 75% 或 7 pt 中较大的值；装不下即失败，不启用上游扩框兜底。独立排版测试之外，还要通过完整页面预处理和 PDF 导出检查。

同栏标题或正文被错误分块时，只有原语法仍开放、字号/字重/颜色一致、几何近邻且合并区域没有其他内容，才拼接原组合并取原框并集。不同字体子集资源仍逐字保留；名称中的原生加号也保持原公式对象。标题可读取紧随其后的源正文片段作为有限背景，但背景不能被补写进标题译文。

姓名附标仅在源作者列表或带连字符的专名、基线及附标与元音的几何关系都明确时，与原字母组成不可拆分的字形组。源文件中的重叠印字仍保留所有原对象；只有同页已证实的普通词，才在模型请求中消除重复字母。跨栏网址则要求左段以 HTTP(S) 路径分隔符结束，右段以紧邻的短路径开始；只移动原字形以补全地址，不凭文字创建新的链接注释。

原生姓名组在创建时登记原页、段落、公式容器和逐字形身份及属性，随后绑定到当前文档与精确翻译输入；不能仅凭公式中的文字像姓名就允许换位。在没有富文本标记的正文中，已登记且唯一的姓名占位符可以适应中文语序移动，但姓名之间的顺序、全部占位符的数量，以及其余数学占位符的顺序必须保持。源句符合已识别的双网络得分语法时，还要检查网络与得分的对应关系。文档、原对象或属性发生变化即失去该许可；这条规则不允许一般数学公式自由重排，也不提供通用语义等价保证。

分类标识的标签、编号和范围继续受保护，编号之间的普通 `and/or` 可译为等义中文连接词。校验同时检查逻辑关系和有序编号，不能仅比较数字出现次数。电气输入／输出定义、训练与预测时间、实验条件与测量量等检查只在原句有明确证据时触发，错误响应走原完整段落重试路径。

中文目标下，完整的短物理量标签 `Voltage U`、`Current I`、`Power P`、`Inductance L`、`Capacitance C` 还须保留量名与单字母符号的明确配对。可带原项目符号；若它由公式占位符承载，必须核对为已注册的原生单项目符号对象。检查要求对应中文量名、原字母及出现次数完整，例如 `Power P` 不能变成“电源”或丢掉 `P`。引用、代码、句内片段、歧义标点和不匹配的符号不由这条整项规则处理；非中文目标保持原有行为。错误结果通过正常校验失败和完整段落重试恢复，不直接修改 PDF 或替换模型输出。

源文档明确的术语定义也在调度前捕获。例如只有原生正文已定义 CWT、A/C 的天气含义时，相关段落才得到相应提示和错义检查；缺少定义或存在冲突时不推断。这类绑定与当前文档及原公式对象关联，整段恢复时仍校验，不能沿用到另一文档。源语法明确时，模型的英文请求视图可以拆开丢失的词间空格、明确指代或关系；原始翻译输入、数字和公式始终是最终校验依据。

源年份范围若被解析成相邻三段，仅在同基线、字体、字号、XObject 和字形邻接关系明确时合并，并保留原字形对象。数字保护标记只用于源语法证明的双组省略比较或明确预测输入/输出关系的整段恢复；其他数字保持可读，恢复后仍校验数字及出现次数。

当源英文明确给出两个并列量、单日目标和前序输入时，模型请求可以将 `the last` 展开为源句已指明的目标，避免模型把它理解成“最后一个序列”。原始输入仍用于全部内容校验，不改公式对象、数字或生成的中文；出现额外候选指代时不做这种展开。当前真实完整摘要探针由一次正常重试修复，未触发预测数字标记恢复；后者目前由离线测试覆盖。这些局部修复不代表五份全文或最终包已通过。

公式识别前，对原字符证明的正文换行恢复独立物理行，防止上游按同一行标识合并跨行公式和普通数字。原生公式描述符、小数与图表标题碎片只有在源语法和字形邻接同时明确时才重新绑定；不从模型回复生成原数学字形。数字检查将合法英文序数词与对应阿拉伯数字统一比较，其他技术标识仍保留独立检查。月份、否定术语及少量已确认的句法错误检查用于触发完整段落重试，不提供一般语义等价保证。

## 存储

应用数据位于 `~/Library/Application Support/PageBridge/`，元数据采用原子 JSON 文件。每份文档拥有原始副本和独立结果目录；导出文件位于用户在保存对话框中选择的目录。API Key 仅在 macOS Keychain 中存储。上游资源与历史缓存可能在其他用户缓存目录，具体位置见 [引擎说明](../engine/README.md#cancellation-diagnostics-and-storage)。测试日志与模型调试响应可能含文档文字，不属于可公开发布的源代码。

## 本地与在线

PDF 解析、排版、对照和导出在本机完成。选择 Ollama 时语言模型也在本机；选择在线厂商时，待翻译文本发送至配置的 API。下载所需字体和版面模型后才具备完全离线运行条件。示例导入不会自动调用 API。

## 兼容与质量边界

只接入 OpenAI Chat Completions 兼容接口的厂商预设；不把只支持其他协议的厂商伪装成兼容端点。模型列表和可用权限以用户账户的接口返回为准，预设是便捷起点。

保留文本层 PDF 的主要结构，不提供通用 OCR。图片中的英语与无法可靠识别的图表短标签不会凭空重写。源文本抽取存在旧字体/Unicode 映射差异，数学质量以源字形和最终渲染为依据。自动门、单元测试、真实模型任务和人工页面复核各自提供不同证据，不能相互替代。
