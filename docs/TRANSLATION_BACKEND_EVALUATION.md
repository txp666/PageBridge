# PDF 翻译后端评估（2026-10-27）

## 结论

本轮七份新文档显示，继续围绕单篇文档增加内容正则和硬性拦截，不能解决版面解析、表格漏译、日文漏译及表单控件丢失。PageBridge 当前 `translation_guard.py` 与 `layout_guard.py` 共 9,142 行；测试能验证这些规则的实现，但不能据此证明新文档的译文质量。

据此选择“原 PDF + 结构化译文”阅读模式，把重建原版 PDF 保留为单独选项。官方上游对照，以及 Docling、MinerU、PaddleOCR 和轻量解析器的同页实测见下文。**当前源码已接入 MinerU 4.0.12 Basic 并将阅读稿设为翻译窗口默认方式，尚未发布。** 新模式不叠加语义或数字正则门控；文件、页码、路径、任务身份、输出可读性、取消和原文件不变等基础约束继续保留。

此前隔离评估没有删除旧 PDF 路径的内容门控，也没有把实验输出接纳为合格译文。新增日期特例已撤回，只保留可复核的诊断补丁；扫描选页的通用输入检查仅用于旧 PDF 模式。新阅读模式使用独立的产物协议与部分完成状态，不受旧 PDF 整篇内容拒绝规则约束。

## 四种解析方案的实际对照

在 macOS 27.0.1 arm64 / 48 GiB 内存上建立独立虚拟环境与模型目录，未改生产锁文件、已安装应用或用户文档库。从上述六份文件取七个问题页：NIST 英文目录 p4、合并表 p28，日文 p7，BatchNorm p3，TI p6，NASA p9，W-9 p1。NASA 页栅格化为 150 dpi 并移除既有文字层，确保测到真实 OCR；W-9 原页保留 23 个 widget。页码均为物理页码。

四种方案统一记录源页，可靠坐标可用时保留；缺坐标块仅提供页级参照（例如 MinerU 目录的 37 块中 35 块没有独立坐标）。块 JSON 再用同一个 `deepseek-flash`、相同提示、temperature=0、相同分批上限翻译；不使用内容正则或语义评分门控。模型只翻译表格文本槽，HTML 行列跨度沿用解析器结果。独立公式保留识别文本，对照阅读器展示原区域裁图；这不等同于公式重新排版正确。逐页保留原始 JSON／HTML／Markdown、输入与模型输出、耗时、版本、源文件哈希及人工检查证据。

上述七页对照使用实验用 HTML／批量文本槽适配器。随后接入应用的实现改为完整块独立翻译、原生阅读视图和表格原区加辅助纯文本，不能把这组实验直接写成正式调用链已经验收。

| 方案 | 本机实测价值 | 直接发现的问题 | 建议定位 |
|---|---|---|---|

耗时为本次单页进程／转换观察值，模型事先准备；不同后端线程配置不同，部分并行运行，不能作为严格性能排名。Paddle 首个目录页还包含首次字体下载，分别留存初始化、推理和导出时间。下载与冷启动单独记录，不混入翻译耗时。

### 影响改造方向的反例

1. **统一强制 OCR 不能解决表格。** MinerU 在 NIST 表上从 28 个视觉行恢复为 5 个逻辑分组，约 4.1 秒；但 TI 强制 OCR 约 32 秒，`±3.0` 被拆为 `±3.` 与 `0 mV`，`1.42` 被拆为 `1.4` 与 `2 V`。两种模式的原始结果均保留。
2. **成功输出结构并不保证数字绑定正确。** 四种方案均没有通过 TI 参数表的列归属复核。保留大量 rowspan／colspan，仍可能把典型值和最大值合在一格；翻译模型无法恢复上游已丢失的结构。
3. **把视觉行当翻译单元会诱发跨块挪译。** MinerU 自动 NIST 表同参数重试返回全部 55 个 ID，但两个尾部短语的译文为空，含义被移到相邻槽。实验适配器因此保留该批原文；这是解析粒度与模型输出契约的问题，不是 MinerU 进程失败。正式实现应按完整段落／逻辑单元分批，并把失败限制到对应块。
4. **扫描解析器没有统一赢家。** NASA 页中 Docling 的句序错误被模型翻译成错误含义；MinerU 与 Apple Vision 的主要句序更完整。MinerU 译文仍重复了标题的第二行，不能据此给整页“无误”标签。
5. **表单保持原件更直接。** 所有结构化译文都只是阅读材料，没有重建 W-9 的可填写控件。点击“原页 PDF”仍可访问保留控件的原件。

### 已接入源码的产品路径（未发布）

新增“对照阅读”产物类型：**原 PDF → MinerU 解析块 JSON → 完整段落独立翻译 → 原生界面阅读稿**。第一阶段只接 MinerU 4.0.12 Basic / ONNX CPU；Docling 等保留为外部实验候选，未提供应用内后端切换。首次使用下载独立的 CPython 3.12.12、依赖和模型，请预留约 4 GB 磁盘空间；这不是模型或安装包的固定下载大小。解析器在本机运行，翻译使用现有 Ollama／兼容 API 服务配置。许可及模型归属见[第三方说明](../THIRD_PARTY_NOTICES.md)。

原文永久保留。阅读界面使用完整原页背景，在原文段落坐标内绘制译文，保持页数、分栏和图表位置；不把段落重排成卡片文章。文字仅在原框内适配字号，溢出时点击展开完整内容。表格、公式、图片和代码保持原位，表格辅助译文在详情中查看，不重建可当作工程依据的新表。块记录原文、译文、源页、可用坐标和完成状态；缺坐标时通过页旁入口查看，不猜坐标。失败块保留原文及重试入口，其余块继续可读；页面解析失败也保留完整原页。现有 PDF 重排导出独立存在，其内容检查不套到阅读稿上。

应用源码已接入阅读稿任务、独立存储、Mac／Windows 阅读界面及失败块重试。重试读取已提交的原文块，不重新解析，保留其他页和块；完整重新生成则替换当前阅读稿及其所选页范围，不合并新旧页。阅读稿尚不能导出为译文／双语 PDF，也尚未接入自身的全文搜索和批注；原 PDF 的现有功能继续可用。新增 Windows 原生 GUI、模型执行和安装包尚未完成验证，不能由共享引擎测试推出跨平台可用结论。

原型材料：`validation/backend-comparison-20261027/` 下的 `corpus/manifest.json`、各后端 `report.json`、`translations/`、`audits/` 与 `review/index.html`。这组对照只有七个有针对性的问题页，不能据此宣称全书准确率、公式无损或 Windows 性能。正式调用链的追加样本、测试与限制另见[验证记录](VERIFICATION.md)；协议见[引擎说明](../engine/STRUCTURED_READING.md)。

## 上游代码检查的直接发现

- 当前锁定的 `pdf2zh-next 2.9.0` / `BabelDOC 0.6.2` 已有 `disable_rich_text_translate`、`translate_table_text` 和 `ocr_workaround` 参数，不需要先升级才能做对照。
- `ocr_workaround` 是为已有识别结果覆盖白色背景等处理，不能等同于一个独立的扫描识别引擎。
- BabelDOC v0.6.2 的[旧 RapidOCR 表格检测器](https://github.com/funstory-ai/BabelDOC/blob/v0.6.2/babeldoc/docvision/table_detection/rapidocr.py) 是兼容性空实现；因此不能仅凭 `translate_table_text=True` 就宣布表格能力已启用。
- 原生兼容模式及重排阅读模式都需要实际页面比较。取消整篇拒绝可能增加可见输出，也可能暴露错误；应分别记录生成率、内容覆盖、数字／公式疑点和版面，而不只比较命令退出码。

## 建议的适配方式

### 已执行的原生上游对照

使用同一锁定依赖和本机 `qwen3.5:35b-a3b-int4`，直接调用官方 `pdf2zh_next.high_level.do_translate_async_stream`，不加载 PageBridge 四个自定义引擎模块，关闭富文本翻译，使用简化提示和原生默认短行处理；英文案例另外设 `translate_table_text=True`。关闭缓存读取，源 PDF 哈希不变。两例均生成全文 N／2N 页输出，但都未通过所选页视觉复核。

| 案例 | 运行结果 | 原译文人工对照 |
|---|---|---|
| NIST 英文 p4、p28 | 50.203 秒；48 页单语、96 页双语 | 目录依然串行；表格正文翻译覆盖增加，但多个单元格出现重复句，不能视为合格修复。 |
| NIST 日文 p7 | 28.150 秒；52 页单语、104 页双语 | 标题及前三段变为中文，但蓝色定义框和最后一整段仍为日文；比基线覆盖更多，仍不合格。 |

这是整体管线组合对照，同时改变了自定义处理、提示和若干选项；不据此归因某一个开关，也不作速度排名。旧 RapidOCR 检测器为空实现，并不意味着文本层表格在所有流程下都不能翻译；本次视觉结果恰好说明应直接检查输出内容，而非根据开关或检测器名字推断能力。两例未进入用户文档库，未作为可交付译文。

### 当前实现边界与后续验证

1. **保留原 PDF 为稳定参照。** 原文页码、书签、链接和交互表单始终来自不可变原文件。译文按源页和块定位，点击可以回到原文。
2. **把解析结果、译文和排版分开。** 结构化 JSON 记录块 ID、源页、可用坐标、类型、原文、译文与状态，由原生视图展示。表格保留原图及辅助纯文本；图片／公式保留原区域。当前没有阅读稿 PDF 导出或译文表格重建。
3. **失败局部化并明确展示。** 某个块不能完成时保留对应原文和“未翻译／需核对”状态，允许重试该块；整篇状态区分完成、部分完成和失败。不要把未译源文与正常译文混在一起而仍统一显示成功。
4. **保留运行安全约束。** 文件损坏、路径越界、任务身份不符、输出无效或取消后提交仍应拒绝。当前不新增数字、术语、引用评分器；用户依据保留的源页核对内容。结构化输出成功不代表解析器没有漏块、错序或数值归属错误。
5. **按实际调用链继续测文档。** 旧 PDF 协议要求单语 N 页、双语 2N 页及零 unresolved；阅读模式使用 `structured-reading` 和 `partial` 状态，允许局部未译。本轮同页原型已覆盖 NIST 目录／表格、日文摘要、BatchNorm 公式、NASA 扫描和 W-9 表单；追加实测要分别记录生成情况、内容缺失、原区定位及人工查看范围，不能把完成数当作准确率。

本轮测试记录见 [验证记录](VERIFICATION.md)。官方上游隔离实验和来源摘记位于本机 `validation/expanded-pdf-20261027/research/`，不会改变用户文档库或已安装应用。
