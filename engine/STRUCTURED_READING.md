# Structured reading engine

This describes the PageBridge **0.5.0 / build 14 release candidate**. Installation, platform and upgrade acceptance is still in progress; see `docs/VERIFICATION.md` for completed evidence. The protocol and processing behavior below do not imply a published release or professionally verified translations.

`worker.py` accepts `action: "translate", outputMode: "reading"` with the existing document, output-directory, language, selected-page and service fields. It keeps the original PDF unchanged and publishes `reading.json` plus an identity/hash-bound `manifest.json` in a new attempt directory. The result event uses `artifactType: "structured-reading"`, `readingPath`, `readingSHA256`, `manifestPath`, page counts and completion counters. The machine-readable contract is `structured-reading.schema.json`.

The parser uses optional **MinerU 4.0.12 Basic / ONNX CPU**, with automatic text/OCR routing. It runs one selected physical page per subprocess, continues after a failed page, and emits an explicit page fallback. Source coordinates are retained only when supplied reliably. Lists and indexes use the original PDF's native text lines when available: font spans within a line remain one passage, while numeric section/page labels remain at their actual coordinates. An index line with dot leaders uses its original character boxes to separate the complete title from its number prefix and page-number suffix; the leaders remain in the original page. Numbers at the end of ordinary titles are not split without dot leaders. No rows are evenly divided or inferred. A scanned list without native line geometry keeps its full text but has no display bbox, so the client exposes its translation through the unpositioned full-text entry. Tables with visible native text retain the original numbers, grid and cell coordinates. Native text labels become individually positioned `sourceType: "table_cell"` blocks; the parent `native_table` keeps faithful native rows and is not sent to the model as a matrix. Each label may retain bounded `translationContext` containing native rows for diagnosis, but that context is not sent to the translator: real tests showed neighboring numbers being copied into short labels. The table prompt translates only the literal source fragment, preserves units/acronyms and unmatched parentheses, and does not complete a neighboring date or sentence. Numeric tokens, including year labels, remain source pixels. Tables without visible native text retain their source region and auxiliary translated plain text. Formula and figure regions remain preserved source content. Clients render those regions from their own original PDF; no parser HTML or image path is trusted by a UI.

Text, heading and list blocks with a region may include `backgroundColor: [R,G,B]`. This optional display hint is the channel-wise median of a few samples just outside the region on a low-resolution RGB render of the original page. Sampling uses the same rotated/cropped `page.rect` coordinate space as the page image; errors default to white and do not fail parsing. This hint is used by the legacy/scanned-page renderer. Older artifacts without the field remain valid and use white by default.

For pages with visible native text, `backgroundImage` holds a base64 PNG rendered from an in-memory copy with only mapped translated glyphs removed using transparent redaction. Photos, watermarks, fills, table values and fine paths remain in the source artwork. `backgroundBlocks` names the only blocks drawn on top, without solid rectangle fills or repainting original table regions over the translation. `foregroundColor` preserves the mapped native text color. Unchanged text, rotated captions and headings that combine multiple native text colors remain original pixels; mixed-color heading translations are still available in the detail view instead of being drawn in one incorrect color; image-only scans keep the existing route. Original PDFs are never saved or modified. A paired, uniform-color soft-mask text shadow may be removed with its native text; unmatched image resources remain intact. Inline formula source crops remain available from the original. Page-local coordinates subtract the displayed page origin after rotation; `decorationsCoordinateSpace: "page"` identifies normalized legacy decoration paths. New backgrounds omit the redundant decoration paths.

Every non-empty text/heading/list/table block is translated independently as a complete passage. Pure decimal numbers and dotted section numbers stay `preserved`, including numeric page footers; they contain no language to translate. Explicit parser page labels retain optional `sourceType: "page_number"` and stay preserved regardless of their text, so Roman page labels need no text heuristic. Explicit parser code blocks use `kind: "code"` and remain `preserved`, without sending their bodies to the translation service; this uses the parser's type rather than content heuristics. Opaque formula markers are mentioned in a prompt only when the source has actual formula attachments. A response must preserve the source marker multiset exactly; an unknown, duplicated, missing or unfinished marker marks only that block `source_fallback`. Empty, truncated or failed API responses also fall back only that block. There are no numerical/semantic scoring rules or whole-document quality gate. A completed task means processing completed, not that its translation has been professionally verified.

To retry blocks, send the same request with the committed `readingPath` and `retryBlockIds: ["p00001-b00002"]`. The engine verifies source hash and languages, reads the retained source passage, skips parsing, updates only those blocks, and publishes a new complete artifact. A changed model is recorded on each translated block. The previous artifact is unchanged. A page with no extracted blocks can be retried by regenerating the reading artifact; this version does not merge page reparses.

The pinned Basic ONNX OCR dictionary has no Arabic alphabet. When `sourceLanguage` is `ar` and a selected page has no extractable Arabic letters, that page becomes `source_fallback` with an explicit capability message and empty blocks. It retains the original image, without attempting OCR or sending guessed text to the translator. If every selected page is in this category, no runtime preparation/download is started. Existing Arabic text layers and other source languages continue through the existing parser path. This is a declared backend capability, not a semantic score or confidence threshold.

## Runtime preparation

`action: "prepare_reading"` needs no translation service. A reading request also prepares automatically when necessary. The UI should explain the first-time component download and roughly 4 GB of required disk space. `engine/setup-mineru.py` exposes the same preparation for development:

```sh
engine/.venv/bin/python engine/setup-mineru.py --runtime /absolute/path/to/optional-runtime --uv /absolute/path/to/uv
```

Default persistent location is `~/Library/Application Support/PageBridge/mineru/4.0.12` on macOS, `%LOCALAPPDATA%/PageBridge/mineru/4.0.12` on Windows, or the corresponding XDG data directory on Linux. `PAGEBRIDGE_MINERU_RUNTIME` overrides it for isolated testing. The optional runtime has its own managed CPython 3.12.12 under `python/`, its own `.venv/`, model files under `home/models/`, and download caches. It does not depend on the app bundle's Python path. The app bundles only the integration files and `tools/uv` (`uv.exe` on Windows); it does not bundle the optional model weights.

`mineru-requirements.txt` pins the optional environment package versions separately from the main engine `uv.lock`; it is not a hash-locked wheel manifest. `mineru-models.json` records 13 tested Basic model/configuration files and their SHA-256 values. Preparation uses the official Hugging Face model source, verifies the files, checks imports/package versions, and atomically writes `ready.json`. Interrupted setup can be resumed; an OS file lock prevents concurrent installations. Runtime inference is offline and never invokes a remote parser. Python-path variables and API/token/secret environment variables are removed from child environments. Translation credentials remain only in the main worker's request memory, are sent only to the normalized selected translation endpoint, and are never written into the artifacts.

Setup/download caches and symlink/hardlink sizes are not an accurate additive package download size. Windows and other architectures require their own installation and execution verification; this file does not claim a completed platform matrix.

## Verification

`test_structured_reading.py` covers partial block/page completion, retry without reparsing or replacing good blocks, unchanged source identity, cancellation before publication, redirect/truncated-response handling, coordinates, model file integrity and isolated managed-Python preparation. The process-tree test requires native process enumeration permission; it is skipped in restricted sandboxes and must also run in a normal host environment.
